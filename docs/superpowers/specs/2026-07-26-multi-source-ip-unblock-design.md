# 多来源 IP 解封设计

## 目标

将 Cockpit IP 自助解封插件从仅支持 iptables INPUT 链，扩展为可检测、查看和解除 iptables、fail2ban 与 firewalld 的 IP 封禁。用户可按来源筛选，或对同一 IP 在所有可用来源中一次性解封。

## 范围与原则

- 支持运行时可检测的 `iptables`、`fail2ban-client` 与 `firewall-cmd`；不存在、不可执行或服务未运行的来源不显示为可选项。
- “全部”表示对当前 IP 的每个可用来源执行解封；一个来源失败不阻止其他来源继续执行。
- fail2ban 解封覆盖所有已发现 jail；firewalld 覆盖运行时和 permanent 配置中的、以该 IP 为 source 且动作是 reject/drop 的 rich rule。
- 仅删除由当前插件明确识别出的 IP 专属封禁规则，绝不执行宽泛的 flush、reload 或删除整条链/整套规则。
- 每次请求仍只接受经严格验证的 IPv4 或 IPv6 地址。来源值使用固定白名单，不传入 shell。

## 后端架构

后端 helper 拆分为三个来源适配器和一个统一编排层。每个适配器提供：可用性检测、列出封禁、解除指定 IP 的封禁。适配器返回同一结构：`source`、`ip`、`rule`、`status` 与可读错误信息。

统一列表接口返回：用户与配额信息、`available_sources`、以及带来源和规则说明的 `blocked_ips`。前端不需要了解系统命令格式。

统一解封接口接收 `ip` 与来源（`all`、`iptables`、`fail2ban`、`firewalld`）。它收集每个目标来源的结果并总是返回结构化 JSON；整体结果为成功、部分成功或失败。只有至少一个实际删除操作成功时，非 sudo 用户才消耗一次每日额度并写入一次历史记录。审计日志包含目标来源、每个来源的结果和规则数。

### 来源实现

- iptables：读取 INPUT 链中的 IP 专属 DROP/REJECT 规则，删除时使用解析出的精确规则规格而非不稳定的行号。
- fail2ban：以 `fail2ban-client status` 枚举 jail，使用各 jail 的 `status <jail>` 读取 Banned IP list，并以参数化命令 `set <jail> unbanip <ip>` 解封匹配项。
- firewalld：通过 `firewall-cmd` 检查服务状态，读取 runtime 与 permanent rich rules；仅解析 source 精确等于 IP、动作含 reject/drop 的规则，并以原始规则文本精确删除相应规则。

命令执行采用参数数组、捕获 stdout/stderr 和超时。命令缺失、服务不可用、无匹配规则、执行失败分别以可区分的结构化状态返回。

## 前端交互与视觉

页面顶部增加“封禁来源”下拉框：默认“全部”，其余选项来自后端的 `available_sources`。切换后即时过滤表格。表格增加“来源”和“规则/位置”列，并为不同来源绘制一致的徽标。

当用户确认解封时，弹窗说明目标 IP 和所选来源；选“全部”时明确写出会处理所有已检测来源。结果消息逐项显示每个来源的规则数、未发现项或失败原因，部分成功使用警告样式而非误报为完全成功。

空状态按当前筛选来源说明未找到封禁；加载、按钮禁用、表格溢出和小屏布局保持一致。中英文文案同步补全。

## 兼容性与权限

安装脚本只检测并提示可选工具，不强制安装 fail2ban/firewalld。sudoers 继续仅授权 helper 本身；helper 不执行 shell 字符串，不接受任意命令或 jail 名称输入。

## 缺陷修复

- 修复近期记录渲染调用 `reverse()` 改写原始数组的问题。
- 用精确规则规格替代按 iptables 行号删除，避免列表与删除之间规则变化导致误删。
- 将“工具/服务不可用”“无匹配规则”和“命令执行失败”分开报告。
- 为解析、来源选择、跨来源部分失败、额度计算和 UI 数据渲染添加自动化测试。

## 验收标准

- 在仅安装任意一个来源工具的系统上，插件仍可正常加载并仅显示可用来源。
- 选择单一来源时，只列出并只解除该来源的 IP 封禁。
- 选择“全部”时，一个 IP 会在所有可用来源中尝试解封，并返回逐来源结果。
- 部分失败不会阻止其他来源执行，且成功一次仅消耗一次配额。
- 无匹配项、权限问题、缺失命令和服务不可用均有准确提示；不会执行超出指定 IP 封禁范围的删除操作。
